# 目录空间统计与进程用途推测

独立 Fastify 后端提供这两项能力，Vue 控制台新增“存储空间”页面和进程行展开面板。Sites 当前没有目录访问或 Pi 进程推测能力。

## 目录视图

`SERVER_WATCH_STORAGE_ROOTS` 为绝对路径 JSON 数组，默认 `["/data"]`。26-server 配置为 `["/data","/data1","/ssd_data"]`；进入 `/data/nasdata` 可单独浏览和统计该挂载点。根目录与请求目录必须是真实目录，不接受符号链接、越界路径或非目录。服务以 wangbin 权限读取，没有提权和文件内容读取接口。

左侧树按需展开当前层，最多显示前 1000 条目录；右侧明细每页 100 条，接口最多 1000 条。单层最多读取 10000 项，超出时明确显示截断。进入目录不会自动递归扫描；点击“统计当前目录”启动后台任务，点击“重新统计”绕过缓存。

占用按 `st_blocks * 512` 字节统计，稀疏文件按实际分配空间计，硬链接在一次扫描内按 inode 去重，归属最先扫描的条目。合计包含当前目录自身元数据块，因此各行百分比不一定合计 100%。与 `df` 卷级用量也不会完全一致（权限、元数据、删除但仍打开的文件等）。符号链接只计自身，不跟随目标；不跨文件系统，也跳过 mountinfo 中的嵌套挂载点。单独进入挂载目录再扫描时，以该目录所在文件系统为统计范围。

扫描用 Python 目录描述符及 `O_NOFOLLOW` 遍历，每次只运行一个子进程，最多排队 10 项，内存保留 100 个任务。单任务两分钟超时、深度上限 128、去重条目上限 500000；权限错误、限额和超时明确显示部分结果。取消或服务关闭会结束子进程。任务不会加入 15 秒监控采样循环，切换页面不会取消后台扫描；再次进入可恢复运行任务。服务器重启不恢复未完成任务。

完成或含权限错误的完整遍历结果持久保存至数据目录的 `storage-cache/`，缓存有效期 15 分钟；取消、失败及超时不持久缓存。磁盘缓存按目录覆盖，失效缓存不返回。实时变化可能导致统计不完整，结果带采集/更新时间。

| 接口 | 参数与返回 |
| --- | --- |
| GET `/api/storage/roots` | `{roots}`，总容量、空闲、普通用户可用量（字节）及可访问状态 |
| GET `/api/storage/list` | `path,offset=0,limit=100`；当前层、根目录、上级、分页和截断标记 |
| GET `/api/storage/cache` | `path`；`{job:null或任务}`，优先返回当前排队/运行任务，否则读取有效缓存 |
| POST `/api/storage/scan` | `{path,refresh:false}`；返回任务，同目录运行中请求合并 |
| GET `/api/storage/job` | `id`；任务状态、各项占用、错误计数和完成后的合计 |
| POST `/api/storage/cancel` | `{id}`；取消后的任务 |

## 未知用途进程的 AI 推测

进程明细展开行或 GPU 抽屉中手动触发，复用默认启用服务商的第一个模型；没有默认项时选择第一个启用且含模型的服务商。通过 Pi SDK 原生工具调用查询 `get_processes`，不额外实现 Agent 循环。必须收到成功的进程工具结果，模型最终输出严格 JSON：用途推测、low/medium 自评置信度和限制。单次最多 60 秒，全局同时一项，同进程同配置请求合并。前端“停止推测”及 HTTP 断开可取消；合并请求共用发起者的取消信号。

证据、PID、命令、用户、GPU 和采样时间由后端从固定采样生成，不采信模型输出的证据；不写入会话或修改监控任务标签。“AI 推测 · 未确认”始终与采集事实区分，不允许 high 置信度。命令参数值仍沿用采集器过滤，不新增“[已脱敏]”占位符。

结果缓存至 `process-inferences.json`（0600），有效期 24 小时，最多保存 500 项。键包含服务器、PID、用户、命令、启动时间、GPU 集合、服务商、模型及连接配置。进程复用或模型配置变化使缓存失效；没有启动时间时包含采样 ID，避免跨采样误用。启动时间由内核 `/proc/stat` 的固定 boot epoch 与进程 start ticks 计算，避免 now-minus-uptime 的微小漂移导致缓存和展开行反复失效。前端支持重新推测，行身份稳定时自动刷新保留展开状态。

| 接口 | 参数与返回 |
| --- | --- |
| GET `/api/process/inference` | `pid`；`{inference:null或有效缓存}`，不会调用模型 |
| POST `/api/process/inference` | `{pid,refresh:false}`；推测、证据、置信度、限制、来源、模型和采样/生成/失效时间 |

## 验证与限制

`pnpm check:storage` 验证允许范围、符号链接、分页、GNU du 独立对照、稀疏文件、硬链接、并发合并、持久缓存、权限、取消和超时。`pnpm check:inference` 验证缓存、进程与模型身份变化、重新生成、并发、取消和事实不被覆盖。`pnpm check:pi` 验证真实 Pi SDK 进程工具往返、JSON 推测及不污染会话；`pnpm check:collector` 验证启动时间跨采样稳定。

26-server 的临时 3031 端口通过真实目录接口、输入拒绝及 GPU4 `qwen3.6-27b` 手动推测检查。浏览器验证逐级浏览、树展开、缓存、重新统计、进程展开、证据和自动刷新。测试数据独立于正式配置/会话。

当前没有登录与多人隔离；按已有私有面板方式使用。大目录应逐级进入后再统计；本轮没有对整个 `/data` 发起递归扫描。正式服务已按用户后续指示恢复，可通过 `http://172.18.132.26:3030` 访问；运行状态及配置备份见 HANDOFF。后续可让 Pi 调用目录工具，但目前 Agent 仍为五个快照查询工具；目录统计由页面手动触发。
